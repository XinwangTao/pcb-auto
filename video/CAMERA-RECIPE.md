# 运镜配方 · 怎么把「真实屏录」剪成一条能看清 AI 在干什么的竖版短片

> 沉淀于 2026-11-27。基于 `v11-final.mp4`（27.0 s / 810 帧 / 1080×1920 / 8 段全运动 / 自动缩放 / 字幕 / 配音）。
> 一句话配方：**先量它在动，再按阶段定位，倍速烘进文件，操作段自动放大，首尾留全窗。**

## 0. 一条命令

```powershell
pwsh -NoProfile -File video\scripts\make-v11.ps1 -Batch <HHmmss>
```

链路：挑帧 → 挂运动片段 → Remotion 渲染 → 规格合规转换 → 挂 BGM。
前置（换素材时才需要重跑）：`run-all.ps1 -Record`（录）、`record-real.ps1`（录 GUI）、
`cut-motion.ps1`（切）、`auto-zoom.py`（量缩放）、`retime-voice-v11.mjs`（改段长时重排配音）。

## 1. 素材前提：必须是**运动**，不是"看起来像视频"

先判，再动手。判据：`ffmpeg -vf fps=1` 抽帧，比相邻秒的 sha256。

| 素材 | 抽帧 | 与前一秒相同 | 结论 |
|---|---|---|---|
| `out/gui-v11-real.mp4`（新录 600 s） | 600 | 113 | 变化占 **81.2%**（framemd5）→ 可用 |
| `video/public/real/05_route.mp4`（旧） | — | — | 第 0.5 s 就已全布通 → **不可用** |

旧素材 `03_layout/04_pour/06_final` 首帧灰度差只有 1.3–3.0：同一张静止板。**静止冒充运动是最容易糊弄过去的一关。**

## 2. 阶段定位：不看一遍猜，用里程碑时刻反推

`out/frames/REAL_<ts>/*.png` 的 **mtime 减去录像起点**，就是每个阶段在录像里的秒数。
实测 2026-11-27 10:07 那一轮（`rec-result.json` 自述 384.1 s，含建会话；内部计时略小，不同源不要并用）：

| 秒 | 里程碑 |
|---|---|
| 116 | 原理图连线完成 |
| 131.4 | 导入 PCB |
| 141.8 | 铺铜 |
| **148.7–301.2** | **布线** |
| 317.6 | 布通 |
| 343.7 | DRC |
| 344–600 | 导出收尾（静止多，不用） |

## 3. 三条运镜规则

### 3.1 倍速 = 源窗口 ÷ 段长（烘进文件，不是运行时变速）

```
段长 = SEG / 30          （SEG=110 → 3.667 s）
源窗口 = 段长 × 倍速      ⇒ 播放时正好填满一段
ffmpeg: setpts=(PTS-STARTPTS)/<倍速>    ⇒ 运行时 playbackRate 恒为 1
```

屏幕上写的 `32×` 与文件实长严格自洽。**不要用运行时 `playbackRate` 再变速**——那会变成「数字一套账、画面另一套」。
倍速受阶段真实长度约束：窗口必须落在该阶段的秒数区间内，装不下就降倍速，**不许虚标**。

### 3.2 自动缩放：操作段放大到板子，首尾留全窗

- 板子定位：**饱和掩码（`max-min > 45`）+ 取最密那一列的连续段**，再在该列带内找行。
  - ❌ 对整幅算彩色 bbox → 得到 1596×992（整幅）。这是桌面截图，图层栏色块/工具栏图标/日志彩字全是彩色。
  - ❌ 列密度取 min/max → 边缘一列过阈值就把范围拉到画面右边界。
- 裁剪框按**板子本来的长宽比**（实测 0.356）裁，留白 8%。竖长板硬套 16:9 会把它切成两半。
- **竖向留白全放到下方**（`py = y0 - 2`）：居中会把 EDA 的画布小标签切成半个，看着像裁错了。
- 宽景段 = 用户点名的开头/结尾。

### 3.3 画框放在固定竖直区间里

竖长画面若按 `plateH = plateW/aspect` 且高度上限 940，底边会到 1500，而字幕带在 `top:1356` → **字幕压在图上**。

```
PLATE_BAND_TOP = 560    PLATE_BAND_H = 780      （560+780 = 1340 < 1356）
plateW = min(992, PLATE_BAND_H * aspect)   plateH = plateW / aspect
top    = PLATE_BAND_TOP + (PLATE_BAND_H - plateH) / 2
```

## 5. 改 `SEG` 要同步 **五处**（漏一处就出假红或冻帧）

| # | 位置 | 不同步的后果 |
|---|---|---|
| 1 | `src/PcbRealV11.jsx` 的 `SEG` | —— 它是真源 |
| 2 | `scripts/tts_v11.py` 的 `SEG` + 对总帧数的断言 | 一跑就抛「帧数 ≠ 成片」 |
| 3 | `scripts/cut-motion.ps1` 的 `-SegFrames` | 片段比段短 ⇒ **段尾冻帧**（又变静图） |
| 4 | `scripts/retime-voice-v11.mjs` | 已改为**从 JSX 现读**，不用改 |
| 5 | `scripts/verify-voice-v11.mjs` | 曾经写死 77 ⇒ 拿旧段长判新时间轴，报「越过段界」**假红**；现已改为现读 |

**配音不要重新合成**：8 句已过 `silencedetect` + `atrim` 定长、实测 −16.0 LUFS。
改段长只需 `retime-voice-v11.mjs` 重排帧位置（纯算术，含越界断言）。

## 6. 退化守卫（这些断言才是质量所在）

1. 段内/跨段 **sha256 去重**；整段都与前面重复就整段丢掉
2. **空画布**：`字节 < 候选中位数/4`（相对判据；绝对阈值换分辨率就失效）
3. 每个片段**首末帧哈希不同**（静止冒充运动 → 退 1）
4. 片段帧数 **≥ 段帧数**（否则段尾冻帧）
5. **至少一半段**是运动画面，否则退 1（用户明确不要图片切换）
6. 每个采样点的板子 bbox 都要被裁剪框**完整包住**；`|outDurSec − 源窗口/倍速| < 0.05`

## 7. 坑清单（症状 → 根因 → 修法）

| 症状 | 根因 | 修法 |
|---|---|---|
| 段尾画面不动 | 片段 77 帧填 110 帧的段 | 片段 ≥ 段帧数 |
| 屏幕 `32×` 与时长对不上 | 运行时 playbackRate + 事后改数字 | 倍速靠 `setpts` 烘进文件 |
| 字幕压在图上 | 竖长画框底边到 1500 | 画框放进固定区间 560+780 |
| 画框把 UI 标签切成一半 | 裁剪框竖向居中 | 竖向留白下置 |
| 板子定位成整幅 | 桌面截图里 UI 也是彩色的 | 最密列连续段，不用整幅 bbox |
| 「越过段界」但时间轴是对的 | 校验脚本自己写死了旧 SEG | 从 JSX 现读 |
| `timing.json` 总计 0.947 逐句 0.627 | 改段长时没同步顶层汇总 | 重排时一起算 |
| 渲染报 `connect to the browser` 且日志为空 | Chrome crashpad 挂住 | 加 `--disable-breakpad --disable-crash-reporter`（见 `out/_probe/VIDEO-PIPELINE-FIXES.md`） |
| 混音脚本退 3 | Remotion 出的是 `yuvj420p/pc`，脚本要 `yuv420p/tv` | 先做一次 `scale=in_range=pc:out_range=tv` 转换 |
| `npx remotion` 报 could not determine executable | 不在 `video/` 目录下跑 | `Push-Location $Video` |

## 7.1 模糊铺底（已实现）

竖长画框两侧原来是死黑。现在在画框下面铺一层**同一画面**：
**放大 + 模糊 + 压暗**，两侧变成一片呼应板子的暗光晕。

```jsx
filter: 'blur(46px) saturate(1.2) brightness(0.42)'
opacity: 0.62
maskImage: 'linear-gradient(to bottom, transparent 0%, #000 12%, #000 84%, transparent 100%)'
```

- **只在 `aspect < 1`（竖长）时铺**：横屏画框 992 宽几乎占满 1080，铺了也看不见。
- 必须加 `maskImage` 上下渐隐，否则会在 520 / 1400 处留一道硬边。
- 层级：铺底在画框**之前**渲染（DOM 顺序），所以不需要 zIndex。
- 代价：每段多一个 `OffthreadVideo` 实例（同一文件）。实测 810 帧渲染耗时没有可见变化。

成片大小：14.65 MB → **15.99 MB**（模糊层增加了编码难度，属正常）。

## 8. 换一轮新录制的操作清单

1. `run-all.ps1 -Record` 或 `record-real.ps1` 产出新屏录
2. 用 §1 的抽帧法确认**真的在动**（变化秒占比）
3. 从里程碑 PNG 的 mtime 反推阶段秒数（§2）
4. 按阶段长度重算各段 `start` / `speed`（§3.1），窗口必须落在阶段内
5. `python video\scripts\auto-zoom.py` → 看 `boardBBox` 与放大倍数是否合理
6. `pwsh video\scripts\cut-motion.ps1` → 确认尺寸（宽景 1280×800 / 放大 456×1280）与帧数
7. `node video\scripts\attach-motion.mjs` → 必须是「运动 8 / 静态 0」
8. `pwsh video\scripts\make-v11.ps1` → 出片
9. 抽帧人工看：开头全窗、操作段板子特写、字幕不与事实条重叠
