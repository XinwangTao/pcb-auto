# SIZES 表 vs 成品实测：w 有大半是准的，h 系统性偏大

> 实测 2026-11-27。分母：`designs/mic-esp32s3-v5.json`（28 器件 / 15 种 LCSC），
> 产物 `out/ESP32S3_Wireless_Mic_V5-20261127-115941`；另用 `test/mutants/base` 里孤立的 0603 做对照。

## 结论先说

**`SIZES` 的 `w` 在好几个封装上是准的（误差 <1%），但 `h` 系统性偏大（+65%~+380%），
15 种里 12 种至少一边偏差超过 20%。** 这说明表里的 `w` 和 `h` **不是同一个量**：
`w` 接近「焊盘跨距」，`h` 更像是本体/外框高度。

因此**我没有改这张表** —— 要改先得回答一个设计问题：布局器要的是焊盘跨距还是本体外框？
那是口径决策，不是测量结果。

## 量具（`scripts/measure-sizes.mjs`）

从**成品 Gerber** 反量，不信设计意图（与 fabcheck 同口径）。四个必须处理的坑：

| 坑 | 现象 | 处理 |
|---|---|---|
| PnP 三种形态 | 真实产物是 **UTF-16LE + TAB + 带单位**（`"25.4mm"`），夹具是 UTF-8 + 逗号 | 探 BOM / 零字节密度；分隔符按 `\t` 与 `,` 数量比；数值去单位 |
| 走线铺铜不是器件 | 只取 D01 时 0603 量出 **971 mil** | 只取 D03 闪点 |
| D03 只给中心不给尺寸 | 只算中心时 0603 量出 **55.1 mil** | 解析光圈 `%ADD..C/R/O/P` 并按形状展开 |
| **过孔也是 D03 闪点** | 密集板上 0603 量出 **150 mil**，同一料号四块板读出 56.4/311.4/311.4/311.4 | 见下 |

### 过孔判据（实测得来，不是猜的）

在 v5 板上数了一次：`GTL` 闪点 252 个，`GBL` 闪点 97 个，而 **GBL 的 97 个全部与 GTL 同坐标**。
过孔穿两层，SMD 焊盘只在一层 ⇒ **「同坐标在 ≥2 层出现」≈ 过孔/通孔焊盘**；
再加「最长边 ≤ 0.8 mm」把通孔焊盘（≈1.8 mm）排除。

效果：v5 板踢掉 182 个焊盘，0603 的高度从 **68.5 → 35.4 mil**（0.9 mm，正是 0603 焊盘高度）。

## 量得住的证据（三条独立佐证）

| 佐证 | 说明 |
|---|---|
| `C14663` = **86.6** mil（宽） | 孤立夹具与密集板**读数完全相同**；且与 PnP 自洽：中心距 55.2 + 2×15.7 = 86.6 |
| `C2913199` = **748** mil（宽） | 与 `relayout.mjs` 里 `PAD_HALF = 374`（×2 = 748）**逐位吻合**，两条独立路径 |
| `C910544` = 141.7 / `C2832146` = 216.5（按 PnP 旋转 90° 归一后） | 对 `SIZES` 的 142 / 217，误差 **0.2%** |

第三条同时暴露另一个维度：**旋转 90° 时 w/h 会互换**，比较前必须按 PnP 的 `Rotation` 归一，
否则会把「旋转」误读成「尺寸差 2 倍」。

## 交付物：把偏差钉成每次 `npm test` 都看得见的数

`test/sizes-accuracy-gate.mjs`（第 23 关，7 条断言）：

1. **量具回归锁**：孤立 0603 实测必须仍在 80–95 mil（宽）/ 25–45 mil（高），
   且与手算 86.6 相差 ≤6 mil。改坏解析器或关掉过孔剔除（高度立刻回到 68.5）都会红。
2. **偏差明示 + 棘轮**：每次打出「声明 119 / 实测 86.6 / 偏大 37.4%」并说明为何未修；
   声明值必须仍是 119 —— 谁改谁同步改闸门与说明，不能悄悄改一个数字。

双向证明：`SIZES` 0603 改 87 → FAIL 2 条；关掉过孔剔除 → FAIL 1 条（高度 68.5 掉出区间）。

## 要真修，缺的不是代码

1. **先定口径**：`SIZES` 到底要「焊盘跨距」还是「本体外框」？现在两者混着。
2. **再要来源**：EDA 库（`eda.lib_Footprint`）或 datasheet 的 land pattern。
3. **然后连带重跑**：改表 → 重跑全部 `designs/*.json` 的布局 → 用 DRC 与 `placement-rules`
   验证没有变差。这是一次需要重跑语料的改动，不适合与「加一道闸门」混在一起做。
