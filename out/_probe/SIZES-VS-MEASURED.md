# SIZES 表 vs 成品实测：我没有改它，但我把偏差钉住了

> 实测 2026-11-27。分母：`designs/mic-esp32s3-v5.json`（28 器件 / 15 种 LCSC）；
> 四块本地已产出的 v5 板 + `test/mutants/base`（孤立 0603 夹具）。

## 起点

几何审查报过：0603（C14663）在 `scripts/relayout.mjs` 的 `SIZES` 里写 `w:119`，
成品 Gerber 里的铜宽只有 76，于是 `bypass_cap_distance` 把 155.5 mil 读成 76，差 2.05 倍。
`SIZES` 是布局器的输入（器件多大、能放多近、板框留多边），但**此前没有任何东西核对过它**。

## 我做了什么

新增 `scripts/measure-sizes.mjs`：从**成品** Gerber 反量每个器件的铜范围。
口径与 fabcheck 一致 —— 量成品，不信设计意图。

三个必须处理的坑（都不是猜的，是撞出来的）：

| 坑 | 现象 | 处理 |
|---|---|---|
| PnP 有三种形态 | 真实产物是 **UTF-16LE + TAB + 带单位**（`"25.4mm"`），夹具是 UTF-8 + 逗号 | 探 BOM / 零字节密度；分隔符按 `\t` 与 `,` 数量比；数值去单位 |
| 走线铺铜不是器件 | 只取 D01 时 0603 量出 **971 mil**（表里 119） | 只取 D03 闪点（焊盘/过孔） |
| D03 只给中心不给尺寸 | 只算中心时 0603 量出 **55.1 mil** | 解析**光圈**（`%ADD..C/R/O/P`）并按形状展开半宽 |

## 关键结论：密集板上这个量具不可信，所以我不改 SIZES

在四块已布局的整板上量同一料号，读数差到无法使用：

```
C11702   56.4 / 311.4 / 311.4 / 311.4
C3850164 344.9 / 147.1 / 147.1 / 147.1
C910544  222.7 / 496.4 / 496.4 / 496.4
```

原因：过孔也是 D03 闪点，没有归属；密集摆放时「最近器件」会把邻件焊盘并进来。
**污染只会把包围盒放大**，所以这里能拿到的只是上界，不是真值。

**凭这种读数去改布局器输入，会把全部 28 个器件的位置带偏 —— 比留着偏差更糟。**

唯一干净读数来自 `test/mutants/base` 里孤立的 C1（0603）：**86.6 × 68.5 mil**，
且与 PnP 自洽：

```
焊盘中心距 2 × 0.7mm = 55.2 mil
+ 两侧各半宽 0.4mm = 15.7 mil × 2
≈ 86.6 mil   ← 与实测吻合到 0.1 mil
```

对比 `SIZES` 的 119：**声明值偏大 37.4%**。审查的方向是对的。

## 交付物：把它变成每次 `npm test` 都看得见的数

`test/sizes-accuracy-gate.mjs`（第 23 关，7 条断言）钉两件事：

1. **量具不腐**：孤立 0603 的实测必须仍在 80–95 mil（宽）/ 55–80 mil（高），
   且与手算 86.6 相差 ≤6 mil。解析器、夹具、PnP 编码任何一处坏了都会让它掉出去。
2. **偏差必须被看见**：每次跑都把「SIZES 声明 119 / 实测 86.6 / 偏大 37.4%」打出来，
   并注明为什么没修。同时**棘轮**住这个已知状态：声明值必须仍是 119，
   谁改了就得同步改闸门与说明，而不能悄悄改一个数字。

双向证明：
- `SIZES` 0603 改成 87 → FAIL 2 条（棘轮 + 偏差幅度）
- 量具不展开光圈 → FAIL 3 条（实测掉到 55.1 / 38.7，掉出所有区间）

## 要真修它，缺的是什么

不是代码，是**一个可信的封装尺寸来源**：EDA 库（`eda.lib_Footprint`）或 datasheet
标称的 land pattern。拿到之后：改 `SIZES` → 重跑全部 `designs/*.json` 的布局 →
用四块板的 DRC 与 `placement-rules` 验证没有变差。那是一次需要重跑语料的改动，
不适合与「加一道闸门」混在一起做。
