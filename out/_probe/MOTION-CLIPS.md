## 三、倍速是算出来的，不是标的

合成里每段 **77 帧 / 30fps = 2.5667 s**（`PcbRealV11.jsx` 的 `SEG`）。取

```
源窗口 = 段长 × 倍速        ⇒  播放时正好填满一段
```

于是屏幕上写的 `32×` 与文件实际时长严格自洽。倍速在 ffmpeg 里用 `setpts=(PTS-STARTPTS)/N` **烘进文件**，运行时 `playbackRate` 恒为 1 —— 不是"数字一套账、画面另一套"。

## 四、怎么防止「静止冒充运动」

`cut-motion.ps1` 对每个片段做**首末帧哈希比对**，相同就退 1 拒绝（实测 8/8 都不同）。`attach-motion.mjs` 再断言三条：
`|outDurSec - srcWindowSec/speed| < 0.05`、`speed > 1`、`firstLastDiffer === true`；
并且**至少一半段必须是运动**，否则退 1（用户明确不要图片切换）。

成片侧独立复核：在 `pcb-bottom / pcb-stitched / pcb-clearance` 三段各连抽 3 帧（间隔 8 帧），三帧互不相同 —— 图片段是做不到这一点的。

## 五、代码落点

- `video/scripts/cut-motion.ps1`（新）— 切片 + 烘倍速 + 断言，写 `video/out/motion/clips.json`
- `video/scripts/attach-motion.mjs`（新）— 把片段挂到 `public/v11/manifest.json` 的 `beats[].video`，并把 `crop/srcW/srcH` 换成视频真实宽高（否则按旧截图宽高比会被拉扁）

## 六、坑

1. **橙色说明行会和倍速矛盾**：原先是「画布在 6–56 秒之间变了 2 次」，那是静态截图时代的描述。现在段是真运动，这句与屏幕上的 `32×` 直接冲突（一个数字两种含义）。已在 `attach-motion.mjs` 里改成「12.8 秒真实操作，5× 加速」。
2. **`crop` 不换会被拉扁**：视频 1280×800（1.6:1）、截图 737×434（1.70:1），沿用旧 crop 会让画面变形。
3. **Remotion 的 `staticFile` 只认 `public/`**：片段必须复制进 `public/v11motion/`，放在 `out/motion/` 渲染时才报找不到文件。
4. 派出去做同一件事的子 agent 跑了 50 分钟没产出（`motion-clips` 最终 failed、无任何文件）。这条链路由主 agent 直接做完并验证，**它的结论不进入本文件**。

## 八、自动缩放：首尾全窗、AI 操作时放大到板子（2026-11-27 11:00）

用户要求：**「AI 操作画板子、画线，然后自动布线的时候，你要适当放大，不然看不清……开头和结尾是现在的视角。
当 AI 开始操作了，就要放大到那块板子的视角。」**

### 怎么找到板子（三次踩坑）

1. ❌ 对整幅算「彩色像素 bbox」→ **1596×992，几乎整幅**。这是**桌面截图**，图层栏色块、工具栏图标、
   日志彩字全是彩色。`frames-stats.py` 那套掩码只适用于纯画布 PNG，不适用于带 UI 的桌录。
2. ❌ 列密度取 `min/max` → 画面边缘只要有一列过阈值，范围就被拉到 `x=1599`。
3. ✅ **从最密的那一列向两侧取连续段**（`run_containing`），再在该列带内找行。

列密度峰值 0.72 落在 `x≈682–903`，而右侧图层栏只有 0.20 —— 板子是最稠密的那一块，这个区分度足够。

**实测结果：板子固定在 `682,118 – 903,741`（222×624），t=160…332 逐帧一致。**
整轮不移动，所以全片共用一个裁剪框不仅够用，而且**更好**：段与段之间不会跳动。

### 缩放参数

| 项 | 值 |
|---|---|
| 裁剪框 | `240×674 @(672,116)`，长宽比 0.356 = 板子本来的竖长比 |
| 留白 | 8%，且**竖向留白全部放到下方** |
| 放大 | 线性 1.48× / **面积 9.89×** |
| 渲染后板子尺寸 | 138×387 px → **约 257×780 px** |
| 宽景段 | `pcb-imported`（开头）/ `pcb-clearance`（结尾），不裁 |

为什么"面积 9.89×"而"线性 1.48×"差这么多：板子是竖长的，横屏画面两侧全是空白，
裁掉那部分就是面积上的巨大放大，但画面内容的线性放大只有 1.48 倍。

### 竖长画面会撞字幕带

画框原来按 `plateH = plateW/aspect` 且高度上限 940 → 竖长画面底边到了 1500，
而字幕带在 `top:1356`，**字幕会压在图上**。改成在**固定竖直区间**内居中：

```
PLATE_BAND_TOP = 560    PLATE_BAND_H = 780      （560 + 780 = 1340 < 1356 字幕带）
plateW = min(992, 780 * aspect)   plateH = plateW / aspect
top    = 560 + (780 - plateH) / 2
```

### 另一个值得记的错

第一版把裁剪框**竖向居中**，结果板子上方那 ~25 px 恰好把 EDA 的
「EDA 画布 005256/1-sma…」小标签切成半个，看起来像裁错了。
改成 `py = max(0, min(y0 - 2, src_h - ch))` —— 板子贴画框顶边、多余高度留在下方，
标签就完整了。
