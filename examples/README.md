# examples/

这里是**真实跑出来的产物**，不是手工构造的样例。

存在的唯一理由：让「可下单性只看 `fabcheck` 的退出码」这句话，你在**不装 EDA、
不生成任何东西**的前提下，两条命令就能自己验证。

## d1 —— 一个只有 1 个器件的小板

```
BOM.xlsx         物料清单
Gerber.zip       打样用的 Gerber + Excellon（打成 zip 是因为一次导出就是一组文件）
Netlist.json     网表
PnP.csv          贴片坐标
TestPoints.csv   测试点
Board.pdf        图纸
```

跑：

```bash
node cli/pcb.mjs fabcheck examples/d1
```

然后 `echo $?`（PowerShell 是 `$LASTEXITCODE`）。

你会得到 **exit 1**，`verdict: FAIL`，只有一条阻断：

```
gerber.copper.thin   总铜图元 27 < 40，疑似零铜
```

这条是**误判**，而且我把它原样留在这里，没有为了让结果好看去改阈值。
原因很直接：d1 只有一个器件 U1，整块板的铜就是 9 个焊盘加 18 段走线 ——
27 个图元对一个「只有 1 个器件」的板是正确的，对「疑似零铜」的判据是不足的。
阈值 `40` 是按常规多器件板定的，它在 d1 这种极小板上没有区分力。

## 为什么要把一条误判放进仓库

因为这个项目的判据是：**闸门必须能被证明它会响，也必须能被证明它什么时候会错。**

只给一个 `exit 0` 的好样本，你没法区分「判据是对的」和「判据永远返回 0」。
给一个 `exit 1` 的样本，你至少能确认三件事：

1. 它真的在检查东西（不是恒真）；
2. 阻断会给到 `file:line` 级别的具体位置和 id，不是一句「有问题」；
3. 它错的时候，错**可复现、可定位、可讨论** —— 你可以自己判断这条该不该算阻断。

## 已知边界

- 这 6 个文件是 `fabcheck` 的**完整**输入集。少任何一个都会新增一条
  `file.missing` 阻断（少 `Board.pdf` → 2 条，只给 `Gerber.zip` → 7 条）。
  所以别删文件来「简化」这个样本，那会把一条已知误判变成一堆缺件阻断。
- 这个目录**没有** `_run.json`。它是一份被单独拿出来的产物，不是流水线的完整运行记录，
  所以 `fabcheck` 输出里 `run` 字段是 `null`。这不是缺失，是事实。
- 它不含 `out/_probe/` 下那些量具要读的统计。`census` **不扫** `examples/`，
  只扫 `out/`，所以这个样本不会污染语料级的通过率数字。
