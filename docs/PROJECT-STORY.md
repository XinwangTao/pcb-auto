# 这个项目在做什么：让 AI 真的去操作 EDA 软件，把一句话变成一块能下单的 PCB

> 沉淀于 2026-11-27。所有数字都有分母和时刻，能自己重算；重算命令见文末。

## 一句话

`pcb-auto` 把「一句中文想法」推到「一包可以交给嘉立创打样的制造文件」，
中间**不点鼠标、不拖器件、不手动画线** —— 全部由程序通过嘉立创 EDA（专业版）的
JS API 与 CLI 完成，并与流水线**自己的 DRC、独立 DRC 复核、独立产物校验、fabcheck** 四方对账。

最近一轮实测（`out/ESP32S3_Wireless_Mic_V5-20261127-005256`，2026-11-27 00:52）：

| 测量 | 结果 |
|---|---|
| 流水线自述 `_run.json.ok` | `true`（errors 0 / envFaults 0） |
| PCB DRC 叶子 | **0**（`drcLeafCount.passed = true`） |
| 独立 DRC 复核（**注意**：`writer` 字段就是 `run-all.ps1`，是运行器而非独立第三方） | 通过（`_gates.independent.json` 六道闸门全 `true`） |
| 独立产物校验 | **19 / 19** 通过 |
| `fabcheck`（**唯一的下单权威**） | exit 0 / PASS / **0 阻断** |
| 耗时 | **410 秒**，attempt 1 一次过 |

这些是**四个不同的问题**，不许互相代证：`ok=true` 只说"流水线自己跑完了"；
`fabcheck` 才回答"能不能下单"；它们都不回答"焊出来能不能用"——**没有一块板被制造过**。

## 同一份设计跔四次：绿不是可复现的性质

同一个设计文件、同一份 `pipeline3.js`，四次运行（每次都建新工程）：

| 目录 | ok | DRC 叶子 | 耗时 | UUID |
|---|---|---|---|---|
| `-20261126-222113` | true | **0** | 362 s | d52289f4 |
| `-20261126-231945` | true | **0** | 456 s | ed7e0a1a |
| `-20261127-005256` | true | **0** | 410 s | 4cc55448 |
| `-20261127-115941` | **false** | **7** | 356 s | cfd0d3aa |

所以“这个流水线能产出 0 违规的板”是已观测的事实，但“可重复地产出”**不成立**。
每次都建新工程（UUID 不同），布线器对新工程的内部顺序不保证与上一次一致。
**报一次结果时必须同时报不可复现这件事。**


## AI 是怎么"操作软件"的

```
core/ops.mjs        ← 唯一实现：5 个操作
  ├── cli/pcb.mjs       CLI 薄壳（零依赖）
  ├── mcp/server.mjs    MCP stdio 薄壳
  └── plugin/index.js   DSH Cordis bundle 薄壳
```

一层实现、三种外壳。**不做平台适配层**，因为复制出来的两份实现一定会漂移，
然后就会出现「文档说 A、插件做 B」。

EDA 侧全部走 headless：`lceda-pro.exe --owner …` 起服务端，`invoke --code-file` 注入 JS 函数体，
在渲染进程里直接调 `eda.pcb_PrimitiveComponent.modify(...)` 这类 API。实测**每一个
`lceda-pro.exe` 的 `MainWindowHandle` 都是 0** —— 它没有窗口，所以：

- 不能靠截桌面来看进度；画面只能由 `eda.dmt_EditorControl.getCurrentRenderedAreaImage()`
  **让 EDA 自己渲染**再落盘。
- 也因此，「AI 在操作软件」这件事只能靠两样东西证明：**画布帧**和**遥测**，不能靠"看起来在工作"。

需要真窗口时（录视频）另有 `scripts/record-real.ps1`：开一个**带窗口**的 GUI 会话，
gdigrab 录桌面，同时跑同一套流水线。

## 为什么这块板特别难

`ESP32-S3 无线麦克风`：28 器件 / 115 连接 / 27 网络，含 RF 模组、MEMS 麦、I2S 功放、
六轴 IMU、Type-C、五个按键。几个必须靠几何推理才能满足的约束：

- **天线正下方不许有铜/器件**（Espressif 要求）→ 模组天线朝 −Y **悬出板边** 272 mil，
  并生成 `NO_WIRES/NO_FILLS/NO_POURS` 三合一禁布区；fabcheck 实测净空带内
  6289 段线段 + 363 个闪点全部在带外。
- **MEMS 麦的封装内部有声孔**，EDA 的间距检查查不到（它只查导体与导体）→ 在**设计文件里显式声明**
  `_copperVoids`，由审计判据核对"盒子落在器件占位内 + 无别的器件侵入"。
- **板框形状必须真的驱动摆放**。这一条最初**根本不成立**：`relayout.mjs` 把 `boardWidthMil`
  读进来只用于事后判越界，每个 x 都是硬编码 —— 把板宽从 1300 改到 1625，**一个器件都不会动**。
  补上"水平意图"（`center` / `edgeL` / `spreadL` / `{of,dx}`）之后，同一基准只改板宽，
  **25/28 器件移动**，不动的 3 个正是贴左边那簇。

## 这一轮真正修掉的东西（都有前后对照）

1. **最后 2 条 DRC 叶子是单位混算**。`errData.position` 是画布单位（mil/10），
   过孔坐标是 mil，代码直接相减 ⇒ 距离恒在 350 量级、永远过不了 40 mil 的门槛，
   于是那条修复路径**一次都没触发过**（`holePairSummary` 恒为 `{total:2, fixed:0}`）。
   修后实测 `from [88.9505,−389.316] → to [83.953,−389.157]`，两条叶子同时消失。
2. **`run-all.ps1` 把「没能复核」当成「查出违规」**，于是把一块零违规的板换成更宽的板。
   改成三态后再查，打出的真因是 `verify-drc.js` **找不到 `lceda-pro.exe`**。
3. **摆放器的板框是输出而不是输入**（见上）。

## 验证是怎么做的（这是项目最硬的部分）

`npm test` 现在跑 **16 道闸门**，合计约 400 条断言。每道闸门都要能回答三个问题：
它能**失败**吗？它在**自己的职责范围内**失败吗？它的**分母**是多少、**时刻**是几点？

- 每道闸门都有红/绿双向证明：故意破坏 → 必须红并退出 1；还原 → 必须重新变绿且**逐字节复原**。
- 闸门自己的 `2` 是"跑不起来"（缺 git / 缺 python），与 `1`（发现失败）严格分开 ——
  否则 CI 上没人分得清"我的代码有错"和"这台 runner 没装 git"。
- `fabcheck` PASS **不等于**"电路对"：它的判据里没有"铜盖住封装开口"这一档，
  所以那是**没查**，不是**查过并放行**。三个测量、三个问题，永不合并。

## 限制（这些不是待办，是边界）

- **没有一块板被制造过。** 全部结论都是"文件层面可打样"。
- 器件来自 LCSC 社区上传件（MEMS 麦、IMU、按键）**无原厂 datasheet**，符号/封装可信度靠人工复核；
  麦克风声孔朝向因此**无法证实** —— 铜层避让做了，但"能不能听见"是未验证。
- 自动布线在约 15% 的设计上会留下 DRC 违规；**重试阶梯会让结果变差**（实测某设计
  SMD Pad↔Track 从 1 涨到 46），所以现在只跑 attempt 1。
- 只支持嘉立创 EDA 专业版 4.1.111（API 面随版本漂移，`@alpha`/`@beta` 接口大量不可用）。
- 平台：Windows（gdigrab、`pwsh`、嘉立创 EDA 只有 Windows 版）。

## 自己重算

```powershell
node cli/pcb.mjs list                                  # 有哪些设计
node cli/pcb.mjs build designs/mic-esp32s3-v5.json     # 出一块板（约 7 分钟）
node cli/pcb.mjs fabcheck out/<产物目录>                # 唯一的下单权威
node cli/pcb.mjs census --settle 180                   # 全语料普查（带时刻）
npm test                                               # 16 道闸门
```

数字口径：任何百分比都要带**分母 + 窗口 + 时刻**。同一个 `out/` 语料在 settle 0 / 180 / 实时扫描下
会给出三个**都成立**的目录数 —— 只写"79 个目录"而不写时刻，这个数字就没有意义。
